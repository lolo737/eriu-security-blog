Know which layer you're standing on

Hypervisors, VMs, containers, Citrix and AVD: what runs on what, in plain English.

Briefing

Earlier this week I was asked about virtualisation and I wasn't too sure about the different kinds. The one I've used most is Citrix: the app lives on a server, and you reach it through a window on your computer. Simple as. The rest is explained below.

The four missions
MISSION 01
Hardware
One real machine: CPU, RAM, disk, network.
MISSION 02
Hypervisor
Slices it up and keeps each VM apart.
MISSION 03
Guests
Each VM thinks it's a real PC. A snapshot is a save point.
MISSION 04
Delivery
Citrix, AVD or Horizon stream it to the user.
Who runs what
Type 1Runs on the hardware. ESXi, Hyper-V, KVM/Proxmox. Servers.
Type 2An app on a normal OS. VirtualBox, Workstation, Parallels.
VM vs containerVM: own OS each. Container: shares the host kernel.
Citrix / AVDDelivery layers. They sit on top of a hypervisor.
BUSTED
Citrix is not a hypervisorA hypervisor runs VMs. Citrix and AVD deliver them to the user. Mix those up in an interview and the interviewer knows.
Ways to lose a life
  • Muddling the layers makes it sound like you've never touched the kit.
  • A snapshot isn't a backup. If the disk dies, the snapshots go with it.
  • Over-allocating CPU and RAM makes every VM on the host slow.
  • A VM on an unpatched host is only as safe as the host.
Cheat codes
  • Draw the layers: hardware, hypervisor, guest OS, app.
  • One example each for Type 1 and Type 2, said without thinking.
  • Hypervisors run the VMs. Citrix and AVD deliver them.
  • Say what you've actually used. Interviewers can tell.
