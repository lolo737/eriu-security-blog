Picture it

First, the one that decides the interview. A hypervisor is the software that carves one machine into several. Type 1 sits directly on the hardware, which is why it's what you find in server rooms. Type 2 is an ordinary app on top of an ordinary operating system, which is why it's what you find on a laptop.

Next, VMs against containers. A VM carries a whole operating system of its own, which makes it heavy and well isolated. A container shares the host's kernel and carries only the app, which makes it light and quick to start.

Last, the bit that trips people up. Citrix, AVD and Horizon are not hypervisors. They're the delivery layer between the user and a VM (or a shared server) running on a hypervisor. The user sees a screen; the files stay on the server.

Level up: giving a VM more

This is the question that matters most in practice. A VM can't ask the server for more by itself. The RAM, CPUs and disk it sees are a slice the hypervisor hands out, so you change the slice at the hypervisor, not inside the guest.

Where you click depends on the platform. In VMware it's right-click the VM, then Edit Settings. In Hyper-V it's the VM's Settings, under Memory and Processor. Proxmox has a Hardware tab, and VirtualBox has Settings then System. Some setups allow hot-add of CPU and RAM while the VM runs, but don't count on it.

Disk has a second half. Growing the virtual disk in the hypervisor does nothing until you extend the partition inside the guest: Disk Management on Windows, growpart and resize2fs on Linux. And more isn't always better. If every VM is given more than it needs, the host runs short and they all slow down.
